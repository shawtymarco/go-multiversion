# Minecraft 1.26.2x registry mapping

Protocol 975 is configured only after Dragonfly finalises its native block
registry. Blocks are matched by namespaced identifier plus all typed state
properties, with Dragonfly's historical block upgrader used only after an
exact match fails.

All 16,899 target block states resolve to the current registry. Of 17,499
native states, 600 states introduced or changed after 1.26.2x use the explicit
target-air fallback. Every native runtime ID resolves to a valid target runtime
ID, including fallback states.

The target item snapshot contains 1,941 entries. Historical
`minecraft:item.*` door identifiers and `minecraft:item.reeds` are resolved
semantically before mapping to the 1,976 native entries. All target items
resolve; 107 native-only items are hidden clientbound and rejected
serverbound. `ItemRegistry` is replaced with the exact historical table.

`CreativeContent` is converted from Dragonfly's filtered native runtime
list. Item and block values are mapped, unsupported entries are removed, and
every surviving `CreativeItemNetworkID` is preserved so the subsequent
`CraftCreative` request resolves the same native entry. The historical 123
groups and 1,844 raw entries remain audit data, not the runtime selection-ID
source. Recipes retain Dragonfly's network IDs while filtering descriptors or
outputs unavailable to protocol 975.

Every fallback and its complete typed block state is recorded in
`data/v975/fallbacks.json`. The report compares Dragonfly
`ba86ce9567d9fe5936201bf6a951a5a133bd8b2a` with
`7c304285e8de55cbef8777e7a40384820a4ac282`; its SHA256 and counts are
pinned in `data/v975/manifest.yaml`.
