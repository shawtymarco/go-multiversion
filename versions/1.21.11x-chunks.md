# Minecraft 1.21.11x chunk and palette audit

Dragonfly `1872684e` and the current native encoder both use sub-chunk version
9. Their network palette format is identical: the storage header contains bits
per index and the network flag, packed indices remain little-endian uint32
words, palette counts and runtime IDs use Varint32, and biome palettes use the
same paletted-storage representation. The 1.26.30 chunk change only corrected
`HighestFilledSubChunk`; it did not introduce a new wire encoding.

Protocol-844 `LevelChunk` and `SubChunk` packet layouts are the same as the
locked protocol-1001 baseline. Later native packet-struct changes are already
translated by the adapter. Therefore protocol 844 needs semantic block runtime
ID remapping, not a separate sub-chunk codec.

The existing generic Dragonfly hook runs before serialisation and cache hashing:

```text
live native chunk
-> map each block palette through Protocol.MapBlockRuntimeID
-> deduplicate mapped palette entries and repack indices/bit width
-> encode version-9 target bytes
-> hash and cache those target bytes
-> emit LevelChunk/SubChunk metadata
```

Biome runtime IDs are unchanged by this adapter. Block entities remain appended
using NetworkLittleEndian NBT and keep their coordinates; the locked sources do
not establish a family-specific block-entity schema change. Native-only blocks
map to target air, but the live world chunk is never mutated.

Dragonfly tests prove fallback-induced palette deduplication, bit-width
repacking, input-chunk immutability, and that mapped bytes are produced before
the blob hash. The protocol-844 integration test proves all 17,499 native block
IDs return valid values in the 15,845-entry target registry.
