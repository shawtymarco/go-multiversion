# Minecraft 1.18.1x chunk audit

Exact Dragonfly `631184735b1b0b09aadc6cd605143d6eee783987` establishes the native target format:

- expanded 1.18 world height;
- sub-chunk version 9;
- signed absolute sub-chunk Y indices and signed request/response offsets;
- network block palettes using target runtime IDs;
- 3D biome paletted storages, not legacy 2D biome columns.

This differs from the v8 output used by some community adapters. The implementation follows exact historical
Dragonfly rather than that tolerated fallback.

## Encoding path

Dragonfly's existing generic `BlockRuntimeIDMapper` hook is sufficient because protocol 486 and native share
the v9/3D-biome container model:

```text
live chunk -> map/deduplicate target block palette -> encode v9 bytes
           -> hash target blobs -> cache target blobs -> send target metadata
```

The live chunk is never mutated. LevelChunk and SubChunk packet layouts additionally convert protocol-486
request-mode sentinels, signed offsets, height-map bytes, raw-payload presence, and cache blob hashes.

## Validation

- generic palette tests cover target mapping, fallback deduplication, and bit-width repacking;
- every one of 17,499 native block runtime IDs maps to an in-range target value;
- exact populated LevelChunk, SubChunk, and SubChunkRequest historical oracles pass;
- CastleOnline automated connections pass cache-off for 1.18.10/1.18.11/1.18.12 and cold/warm cache for
  1.18.12 while receiving a complete chunk path;
- native 2169, protocol 1001, protocol 975, and protocol 827 deployment matrices pass after the transport change.

Visual verification with a real 1.18.10-1.18.12 client is still required before replacing the automated mark
with a real-client support claim.
