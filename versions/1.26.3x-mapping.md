# Minecraft 1.26.3x registry mapping

The protocol-1001 mapping is built only after Dragonfly finalises its current
block registry. Block identity is the namespaced identifier plus every sorted
state property. BDS byte booleans and Dragonfly bool values are normalised to
the same network byte; all other numeric NBT types remain distinct.

Historical runtime IDs reproduce Dragonfly `705b8460`'s stable FNV-1 name sort.
Old states are first matched exactly, then normalised with the same
`worldupgrader/blockupgrader` path used by Dragonfly for historical disk
states. All 16,913 target states resolve to the current registry. Of 17,499
native states, 586 states introduced or changed after 1.26.3x use the explicit
target-air fallback.

Items map by exact identifier. All 1,933 target items resolve to the 1,976
native vanilla items; 43 native-only items are hidden from clientbound stacks
and rejected if received from an old client. `ItemRegistry` is replaced with
the historical table. `CreativeContent` is converted from Dragonfly's filtered
runtime list: item and block runtime IDs are mapped to protocol 1001, unsupported
entries are omitted, and every surviving `CreativeItemNetworkID` is preserved.
Preserving that selection ID is required because Dragonfly resolves
`CraftCreative` requests against its native filtered creative slice; assigning
IDs from the raw 1,875-entry historical blob can select an unrelated native
item. The historical 123 groups and 1,875 creative entries remain pinned as
audit data, not as the runtime creative packet source. Recipes preserve
Dragonfly's server network IDs while filtering any descriptor or output absent
from protocol 1001.

Every fallback, including complete typed block properties, is recorded in
`data/v1001/fallbacks.json`. Its native baseline is Dragonfly `ba86ce95`, its
target is `705b8460`, and its SHA256 is pinned in `data/v1001/manifest.yaml`.
The report is reproducible through CastleOnline's
`TestMinecraft1263xRegistryIntegration` with `DFMV_FALLBACK_REPORT` set.
