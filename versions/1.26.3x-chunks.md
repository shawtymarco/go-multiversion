# Minecraft 1.26.3x chunk conversion

Dragonfly encodes protocol-aware block palettes before cache hashing through a
generic `BlockRuntimeIDMapper` capability. The protocol-1001 adapter implements
that capability without Dragonfly importing a historical protocol package.

For every block storage, the encoder maps native palette values, deduplicates
fallback collisions, recalculates bits per index, repacks all 4,096 indices,
and leaves the live world chunk untouched. The same encoding object is used by
full `LevelChunk`, cache-enabled blobs, `SubChunk` responses, and cache-miss
storage, so xxhash values always describe the target bytes. Biome palettes are
unchanged because the locked Dragonfly history contains no biome registry data
change for this window.

The chunk codec itself is byte-identical between Dragonfly `705b8460` and
`ba86ce95`. Packet model changes for `LevelChunk` and `SubChunk` remain in the
wire adapter. Block entities stay appended with NetworkLittleEndian NBT and no
schema rewrite because the locked sources show no historical block-entity NBT
change. Tests cover palette fallback deduplication, bit-width shrinkage, input
immutability, and hashing only after target encoding.
