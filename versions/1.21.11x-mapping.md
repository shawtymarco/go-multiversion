# Minecraft 1.21.11x registry mapping

The protocol-844 mapping is constructed only after Dragonfly finalises its
current block registry. Historical blocks use the exact 15,845-state snapshot
from Dragonfly `1872684e`. They are keyed by identifier plus every typed state
property, then passed through the same worldupgrader schema used by Dragonfly
when an old state needs semantic upgrading.

All target states resolve to the current registry. Of 17,499 native states,
1,654 states introduced or changed after 1.21.11x use the explicit target-air
fallback recorded in `data/v844/fallbacks.json`.

The historical item registry contains 1,888 entries. Item identifiers are
first upgraded with Dragonfly's `itemupgrader`; the ten historical
`minecraft:item.*_door` aliases and `minecraft:item.reeds` are resolved to
their current semantic identifiers. The original historical names remain in
the clientbound ItemRegistry. All target items resolve, while 160 native-only
items are hidden clientbound and rejected if received from an old client.

CreativeContent is derived from Dragonfly's actual filtered runtime packet.
Item and exact block runtime IDs are mapped, unsupported entries are omitted,
and each surviving `CreativeItemNetworkID` is preserved so serverbound
CraftCreative requests select the same native item. The raw 120 groups and
1,810 entries remain audit data rather than the runtime packet source.

Current shaped, shapeless, smithing, potion, and container-change recipes keep
their Dragonfly network IDs while unmapped inputs or outputs are filtered.
Protocol 844 still carries furnace recipes separately, so the exact 251-entry
historical furnace snapshot is mapped and appended without inventing recipe
network IDs; that historical wire type has no network-ID field.

The fallback report is SHA256
`893c63520f286239badb720ecd5450f819f9d128a2fb8230b80e13c61c800626`.
CastleOnline's `TestMinecraft12111xRegistryIntegration` reproduces the mapping
counts and verifies every native block maps to a valid target runtime ID.
