# Minecraft 1.26.2x chunk conversion

The protocol-975 adapter implements Dragonfly's generic
`BlockRuntimeIDMapper` capability. Dragonfly applies this mapper while
encoding each connection's network chunk, before blob hashing and cache
storage, so protocol-specific bytes and hashes cannot diverge.

For every block storage, the encoder maps native palette values, deduplicates
fallback collisions, recalculates bits per index, repacks all 4,096 indices,
and leaves the live world chunk unchanged. The same encoder covers
cache-disabled `LevelChunk`, cache-enabled blobs, `SubChunk` responses, and
cache misses.

The underlying Dragonfly chunk codec and legacy state blob are identical
between the locked protocol-975 target and native baselines. Protocol-specific
`LevelChunk`, `SubChunk`, and `SubChunkRequest` packet layouts remain in
the wire adapter. Biome palettes use the unchanged numeric registry; generated
biome-definition noise data has its own protocol-975 wire conversion. Block
entities remain attached and use NetworkLittleEndian NBT because the locked
sources show no block-entity schema change.

Registry integration checks every native block mapping. Existing Dragonfly
palette tests cover fallback deduplication, bit-width changes, input
immutability, cache-on/off encoding, and hashing only after target mapping.
