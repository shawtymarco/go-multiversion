# Minecraft 1.18.1x registry mapping

Historical data is copied from Dragonfly `677c8fa1753d662e115e9c610dfe334daed2d265`; the blobs are identical to
the 1.18.10 update commit `631184735b1b0b09aadc6cd605143d6eee783987`.

## Registry evidence

| Registry | Entries | Source |
| --- | ---: | --- |
| Block states | 7,946 | `server/world/block_states.nbt` |
| Item runtime IDs | 1,091 | `server/world/item_runtime_ids.nbt` |
| Creative entries | 1,388 | `server/item/creative/creative_items.nbt` |
| Legacy state upgrades | 3,307 | `server/world/chunk/legacy_states.nbt` |
| Default biome definitions | 71 | protocol-486 gophertunnel connection constant |

The production native comparison contains 17,499 block states and 1,976 items.

## Mapping result

- Every native block runtime ID maps to an in-range target runtime ID.
- 9,617 native-only block states use the explicit `minecraft:air` fallback.
- 926 native-only items are hidden clientbound.
- 13 exact historical target items have no current semantic equivalent. They remain in the StartGame item
  registry for target fidelity but are never advertised in converted creative content and are rejected
  serverbound.
- The 13 target-only entries are old experiments/internal block items such as frog/firefly experiments,
  mysterious frames, hanging coral internals, tripwire, and debug stick.

`data/v486/fallbacks.json` records every block, native-item, and target-item fallback. Its normalized SHA256 is
`b22f883718c52fb458bbbc5207c266cee1aec3403a12948ca3c95186e3a88622`.

## Creative and recipes

- Converted CreativeContent is built from Dragonfly's actual filtered native list.
- Unsupported entries are removed and surviving `CreativeItemNetworkID` handles are preserved.
- Protocol 486 has no creative groups on the wire; current groups and group indices are omitted.
- CraftingData retains shaped, shapeless, shulker-box, multi, potion, and potion-container recipes whose
  numeric target ingredients and outputs all resolve.
- Tag/MoLang-only ingredients and post-1.18 smithing/trim recipes are removed because protocol 486 has no
  equivalent wire representation.

CastleOnline integration tests initialise the complete production registries, validate all native block
outputs, preserve a nontrivial creative selection handle, and pass the packet round trip.
