# Minecraft 1.21.10x registry mapping

The protocol-827 mapping is constructed only after Dragonfly finalises its
current block registry. Historical blocks use the exact 15,285-state snapshot
from Dragonfly `93c84812`. They are keyed by identifier plus every typed state
property, then passed through the same worldupgrader schema used by Dragonfly
when an old state needs semantic upgrading.

All target states resolve to the current registry. Of 17,499 native states,
2,214 states introduced or changed after 1.21.10x use the explicit target-air
fallback recorded in `data/v827/fallbacks.json`.

The historical item registry contains 1,836 entries. Item identifiers are
upgraded semantically while their original names remain in the clientbound
ItemRegistry. In addition to the established `minecraft:item.*_door` and
`minecraft:item.reeds` aliases, `minecraft:item.chain` maps to Dragonfly's
current `minecraft:iron_chain`. All target items resolve; 213 native-only items
are hidden clientbound and rejected if received from an old client.

CreativeContent is derived from Dragonfly's actual filtered runtime packet.
Item and exact block runtime IDs are mapped, unsupported entries are omitted,
and each surviving `CreativeItemNetworkID` is preserved so serverbound
CraftCreative requests select the same native item. The raw 113 groups and
1,738 entries remain audit data rather than the runtime packet source.

Current shaped, shapeless, smithing, potion, and container-change recipes keep
their Dragonfly network IDs while unmapped inputs or outputs are filtered.
Protocol 827 carries furnace recipes separately, so the exact 231-entry
historical furnace snapshot is mapped and appended without inventing recipe
network IDs.

The fallback report is SHA256
`5ec7c1e05fb5d7acca08712bf8af6ffea2adcdb9c19922eb025657fc3c01862d`.
CastleOnline's `TestMinecraft12110xRegistryIntegration` reproduces the mapping
counts, verifies every native block maps to a valid target runtime ID, and
round-trips a preserved creative selection handle.
