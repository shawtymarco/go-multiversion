# Minecraft 1.21.10x chunk and palette audit

Dragonfly `93c84812` and the current native encoder both use sub-chunk version
9. Their network palette format is identical: the storage header contains bits
per index and the network flag, packed indices remain little-endian uint32
words, palette counts and runtime IDs use Varint32, and biome palettes use the
same paletted-storage representation.

Protocol-827 `LevelChunk` and `SubChunk` layouts are the same as the locked
protocol-844 baseline. Later native packet-struct changes are already
translated by the adapter. Protocol 827 therefore needs semantic block runtime
ID remapping, not a separate sub-chunk codec.

Dragonfly's generic protocol hook runs before serialisation and cache hashing:

```text
live native chunk
-> map each block palette through Protocol.MapBlockRuntimeID
-> deduplicate mapped palette entries and repack indices/bit width
-> encode version-9 target bytes
-> hash and cache those target bytes
-> emit LevelChunk/SubChunk metadata
```

Biome runtime IDs are unchanged by this adapter. Block entities remain
appended using NetworkLittleEndian NBT and keep their coordinates. Native-only
blocks map to target air, but the live world chunk is never mutated.

Dragonfly tests prove fallback-induced palette deduplication, bit-width
repacking, input-chunk immutability, and mapped bytes before blob hashing. The
protocol-827 integration test proves all 17,499 native block IDs return valid
values in the 15,285-entry target registry.
